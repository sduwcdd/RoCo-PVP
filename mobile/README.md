## 0.8 PVE轻量模式与性能修复

覆盖安装`mobile/build/roco-mobile-android-internal-0.8.apk`，在连接页的“助手模式”选择PVP或PVE。默认PVP保留现有完整战况面板，PVE只显示当前敌方精灵、性格及增减方向、体重、声音参数和奖牌提示。选择会保留，建议在开始采集前选好；对局中切换时等待下一场入场通知。PVE悬浮窗提供连接和敌方两页。

## 0.7 解析积压与变动头字段修复

0.6返回的实录首次错误为`Decoder queue full`，没有转发或镜像错误。原队列按128段计数，登录等大消息的递归解码形成积压。手机版现在对当前战况跟踪器不使用的已知非战斗消息校验封装和顶层线格式，保留原始记录供离线完整解析；战斗及未知消息保持完整解析。计数另列`deferred_nonbattle_records`，不将其当作字段解码成功。

队列保留顺序，最多1024段，并增加8 MiB总字节预算，超限仍明确暂停分析。实录还出现6个空请求的外层[12:16]值为46384，说明此前将该字当作固定版本值的假设有误。已确认手机布局改为原样保留该字段，不赋予含义，继续校验操作码前缀、回显、长度、序号、尾标及线格式。

两份用户实录共1044个协议帧均通过离线完整解析。直接从APK加载后突发输入新样本的460段字节，0.6在队列128段时暂停，0.7完成全部573帧，最终队列为0。相同0.7源码下的完整解码/优化模式，最终战况快照哈希相同，本机耗时16.833/6.308秒；这是本机回放测量，手机延迟仍待实测。新增样本含一场大世界战斗，对应4条进场、回合及结束通知，双方队伍数为6和1；尚未据此验证手机PVP 6v6。

32项针对性Python检查通过。共享解析器默认完整解码，桌面消费者继续使用默认路径。游戏转发器及伤害规则未修改。验证细节见[记录](../docs/verification/android-protocol-queue-20261111.md)。

## 0.6 真机样本兼容修复

用户返回的0.5协议样本已在本地离线核对。手机上行存在版本值0、操作码前缀0078及操作码回显组成的固定布局，原解析器对该布局仍要求字段表完全匹配并拒绝空正文，导致登录请求的新增嵌套字段和合法空请求暂停分析。

0.6对这一已观测布局保留严格的长度、序号、填充、线格式及已知字段类型检查，接受空请求，并完整保留字段表暂不识别的字段。未知布局继续要求完整字段表匹配；未解决的战斗字段继续阻断战况推断。线上方向与静态名称表方向不同的通知单独标记，静态映射保持原始来源。

同一份414段字节记录中的471个协议帧，修复前有28个未识别，修复后448个业务帧和23个控制帧均得到记录，未识别数为0。编译后端重放同一份实录时分析保持运行，439条业务记录取得字段表对应，其余9条按特殊格式或未知消息保留。样本未包含实际对战，真机安装后进入PVP仍待验证。核对记录见[验证说明](../docs/verification/android-protocol-20261111.md)。

## 0.5 协议样本采集

内部版在每次开始采集后，自动保存已识别为游戏协议的有序TCP字节，包含握手密钥及后续双向密文。HTTP/TLS流量不写入样本；最长3分钟、最多16 MB，保留开头数据，达到上限后停止追加。战况分析失败后，网络转发继续，样本收集再持续15秒。采集队列丢失数据会在样本中明确标注，不作为完整观测。

真机复现步骤如下。

1. 覆盖安装当前内部版，完全退出游戏，再在助手中点击“开始采集”。
2. 点击“打开游戏”。如果出现“分析已暂停”，保持游戏联网等待20秒；如正常识别，可进入一场对战并操作一两回合。
3. 返回助手，展开“连接诊断”，点击“导出协议样本”，在系统文件选择器保存ZIP。
4. 先将ZIP通过私密渠道提供给开发者，再停止采集。重新开始采集会替换本机上一次字节记录。

ZIP包含`manifest.json`、`streams.jsonl`和`diagnostics.json`，绑定构建、源码哈希、图鉴快照及流顺序，同时记录手机型号、Android和游戏版本。包含会话密钥和账号流量，请按敏感资料保管。文件仅在APP私有目录生成，由用户选择导出位置。

开发者可在根目录离线核对，不启动VPN或游戏连接，输出报告只含结构信息。

```powershell
.venv-rkpp/Scripts/python.exe scripts/replay_mobile_protocol.py "收到的样本.zip" --out artifacts/app/mobile-replay-report.json
```

已通过24项Python针对性测试、6项移动界面检查、编译后端的构造样例采集/导出，以及公开历史样本的12个加密业务帧回放。Android文件选择器及用户手机实际协议仍待真机验证。此前外层值0被错误拒绝的修正已纳入0.5。

## 0.4 开发修复

### 0.4之后的源码修复与协议参考

2026-11-11的0.4真机诊断明确出现外层值0、内层标记0101。新增schema兼容分支原来限定外层值1，已修正为接受0或1，与既有v14路径的范围一致，仍要求完整外层和字段校验。修正已随0.5打包；真实请求的完整字段与尾部仍无法由旧版结构诊断恢复。

本轮检索后核对的上游包括 [rocom-parse 协议文档](https://github.com/whoisnian/rocom-parse/blob/b07d99408b6562868e14f12ca2659fde739bad0b/docs/protocol.md)、[rocom-capture](https://github.com/whoisnian/rocom-capture/tree/cabf97c0e9c7a7bdced4273407177b77da177d76) 和 [RKPP](https://github.com/yuzeis/Roco-Kingdom-Protocol-Parser/tree/803d0fd6a19a6b244f557825129fea28d0675a03)。rocom-capture记录手机流量解析，但部署在Linux网关。rocom-parse明确保留部分上行体供调试，场景移动请求还存在额外变长尾部；不能由其下行解析成功推定所有客户端请求和PVP消息均已兼容。

另从 [rocom-helper公开夹具](https://github.com/innovationb1ue/rocom-helper/tree/ae4459225cb23e83ff235e0e58fdad79524ae58d/tests/fixtures/packets) 抽取11段记录的66个样本检查结构，其中两段含ACK，可将12个原始密文帧通过现有共享解密与信封解析器回放，12个均产出记录。19项针对性测试通过。这些公开历史夹具没有证实与用户手机格式相同，也没有替代手机实测。研究文件仅在本地artifacts中保留，未作为用户数据或新游戏真值导入。

0.3真机诊断显示首个客户端业务帧的解密尾标、外层标记及长度均通过，但业务信封未被识别。0.4在原解析路径之后增加固定偏移的兼容分支，逐项校验外层序号、版本、长度、尾标以及已知请求schema的完整字段和线类型，不扫描任意偏移或绕过未知消息校验。解析暂停时保留首个具体错误，新增内层标记与候选操作码诊断。

18项针对性测试通过；使用真实ZoneLoginReq字段定义构造的464字节加密帧已跑通握手、解密、业务解析链路，畸形数据仍被拒绝。这是构造样例，用户提供的真实帧没有原文，实际手机兼容性仍待0.4反馈。诊断中的IPv6 HTTPS超时与本次业务信封拒绝分别记录。

### 0.3 已完成修复

用户提供的0.2手机诊断显示：游戏登录握手已被读取，转发错误为0，但第一个0x4013业务帧解析失败，随后旧错误处理主动关闭VPN。因此，反复点击重新连接会再次中断游戏连接。0.3将网络转发与分析错误分开：解析失败、镜像队列满时暂停分析并清除旧估计，保留健康转发；真正的转发器故障、用户停止和系统撤销授权仍关闭VPN。

默认悬浮窗改为48dp可拖动标签，点开后使用屏幕可用高度。顶部提供收起和关闭按钮，内容用我方、敌方、回合三个大触控标签切换。首次点开才加载悬浮网页，关闭面板后采集继续。

新增有界解码结构诊断 `decode_issues`，区分解密、业务信封未识别、解析异常和缺少战斗schema，并记录方向、帧长度、对齐情况和已知标记位置。诊断不含握手密钥、密文或明文。已用构造协议验证27字节握手扩展和共享加密解析链路；该检查不能证明用户手机的首个业务包已兼容，仍需新包真机反馈。

## Android 内部开发版

支持 Android 10 / API 29 及以上，arm64-v8a 和 x86_64。当前本地内部测试包为 **0.7**，位于 `build/roco-mobile-android-internal-0.7.apk`，配套记录为 `build/android-0.7-verification.json`。已完成本机编译、签名与包内资源校验，尚未安装到用户手机验收。0.7沿用0.3至0.6的签名，可覆盖安装。更早版本签名可能不同。

1. 在手机安装内部 APK，打开“洛克同机助手（内部版）”。
2. 首页点击游戏选择卡，搜索并确认实际游戏应用，再点“开始采集”授权 VPN。新版会优先匹配“洛克王国：世界”，不会默认采集应用列表第一项；运行中诊断另显示实际采集包名。仅选中应用经过本机转发器，没有远程代理。
3. 点击“允许悬浮窗”，在系统设置允许显示在其他应用上层；返回后可拖动顶部栏，点击顶部栏收起或展开。
4. 开启采集后**完全退出并重新打开游戏**，使解析器能够观察握手。只切换后台或直接进入对战可能继续使用旧连接。可点“打开游戏”启动已选游戏。
5. 底部切换连接、我方、对方、回合和图鉴，宽屏另有双方对照。首页分别显示网络采集、握手和对局识别，不把 VPN 启动当作战斗解码成功。通知栏或首页“停止采集”会撤销本机 VPN。
6. 仍无数据时，展开首页“连接诊断”并点“复制诊断信息”。包括实际采集应用、TCP/UDP 数量、协议分类、握手与业务计数及错误；不包含密钥、原始报文或个人对局。将这些诊断文字提供给开发者，才能继续核实真实手机协议。

“VPN 已启动”只说明转发器运行；识别到握手及真实战斗报文后才能显示对局。尚未完成真实手机游戏协议验证。手机已有其他 VPN 时，系统可能要求替换当前 VPN；系统行为参见 [Android VPN 文档](https://developer.android.com/develop/connectivity/vpn)。

已进行 Android 模拟器验证：内嵌 Python、资源身份校验、同源 HTTP/HUD、JNI；独立测试应用实际经过 TUN → HEV → 本机 SOCKS → 出口的 TCP/UDP 双向转发；用户停止清理及悬浮窗显示。该验证不能代替真实游戏登录、战斗协议和厂商后台限制的实测。

0.2 修复了旧版仅镜像 8195 端口的盲区，改为各 TCP 连接首段有界识别。已识别 HTTP/TLS 等非游戏流只继续转发，不送战斗解析器；这是协议识别，不是任意 TLS 解密。业务包早于握手时保持等待，不因缺密钥立即停止 VPN；真正解密失败或战斗协议解析失败会明确暂停分析并保留健康游戏转发。非战斗未知消息单独计数，不把原始字段树当作已知语义。计数在普通连接关闭后保留。

本轮 10 项小型边界测试和两条主机内嵌引擎加密管线通过；模拟器 3 项检查还包含经实际 VPN 的 18082/18083 非标准端口 → 握手 → 共享解析器 → HUD，两条构造协议场景覆盖未知非战斗消息及缺握手后恢复。它们是明确标注的测试夹具，不是实际手机游戏抓包，不进入发布 APP。未修改伤害、技能或对战结算规则。

## 共用规则与构建

`python/roco_mobile.py` 接收原生转发器提供的有序 TCP 字节，调用已有协议解析器、BattleTracker 和 HUD 发布流程。`shared/index.html` 只负责手机布局，伤害与配置推断继续使用现有实现。HTTP 仅监听 `127.0.0.1`，保留原有 Host/Origin 校验。缺失握手、队列溢出和解析错误均可见，分析暂停后停止展示过期战况。

在仓库根使用已安装 `cryptography` 的 Python 3.13 构建环境生成配套资源；当前验证过的 `.venv-release` 可用，采集环境 `.venv-rkpp` 不保证含有打包依赖：

```powershell
.venv-release/Scripts/python.exe scripts/build_mobile_resources.py --android-source-stage
Set-Location mobile/android
./gradlew.bat assembleDebug
```

JDK、SDK、Python 的本机路径按 `android/local.properties` 与 `ROCO_BUILD_PYTHON` 配置。依赖固定版本及来源见 [Android 依赖记录](android/DEPENDENCIES.md)。Android 编译器需要临时 `.py` 输入，Chaquopy 在 APK 内编译为 `.pyc`；完成构建并核对包内内容后删除 `mobile/build/generated/android-python/`。下次构建重新生成，不改动引擎原始源码。

当前手机版使用字节码和认证加密资源。APK 属内部开发包，可被逆向，不作为正式保护版本分发；release 构建已阻断。生成资源、临时编译输入及签名材料保存在本机。安卓0.3内测包通过同仓库Releases的预发布 `android-v0.3.0-internal` 提供，附带SHA-256与验证记录；源码与跨设备构建步骤见 [设备交接](../docs/DEVICE_HANDOFF.md)。
