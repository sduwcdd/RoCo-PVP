1. **主资料直接数据**：BWIKI 的种族值、30 性格的增减方向、完整属性组合表、技能与特性描述、术语。它们可证明该版本资料的内容，但不等于游戏内部执行代码。
2. **作者公开实现**：Roco Arena 的前端六维计算代码及计算说明；Roco Showdown 的计算原理。可以精确复现各自的计算口径，并且两者存在可产生不同整数结果的差异。
3. **作者声称的实测**：Arena 给出若干观测值；本次未取得其原始录像或逐回合证据，因此不能登记成本项目已完成的真实校准样本。
4. **官方已确认精确公式**：本次未获得。完整精度、所有状态边界和完整时序仍未证明。

按用户最新要求，技能与特性全部以 BWIKI 为准。下文外部公式**仅作为待核验对照资料，不是平台默认公式，也不用于自动填补 BWIKI 缺失的参数**。如果未来经过明确审查后采用数值参考组件，仍需显式命名并保持 `calibrated=false`。不能把不同网站的步骤拼成一个“已还原公式”，也不能将参考预测直接当作训练真值。本次未实现任何公式代码。

## 能力值参考：Arena 60 级五星口径

来源：[Arena 计算说明](https://rocoarena.com/calculation-notes)、实际发布的 [damage-ui-B2QaE2G3.js](https://rocoarena.com/damage-ui-B2QaE2G3.js)。该说明引用[凡进条的属性推算视频](https://www.bilibili.com/video/BV13PEZ6hEDT/)；本次未能读取视频内容，不把视频当已独立核实的证据。

变量：`R` 为种族值；`I` 是该实现使用的原始个体资质值；`n` 为性格倍率。该作者明确说明界面 `+10` 对应 `I=60`，并在代码中将 `I` 限制在 0..60；这只能证明该实现的编码关系，不能推出所有游戏模式允许任意 0..60 分配，也不能据此推断总点数限制。

精确复现该实现的步骤（仅限 60 级、五星、无额外修正）：

```text
g = float32(R × 0.01) + I × 0.005
非生命 core = round_JS(float32(110 × g + 10))
生命   core = round_JS(float32(170 × g + 70))
非生命 final = round_JS(core × n + 50)
生命   final = round_JS(core × n + 100)
```

`n`：提升 1.2、降低 0.9，其余 1。代码只在上述两个位置调用 `Math.fround`；没有对 `I×0.005` 或每一个运算单独 float32 化。`round_JS` 是 JavaScript `Math.round`，正数的半值向上，不能直接以 Python 的偶数舍入代替。该实现还有一个用户 offset，作为最终整数之后的人工修正；它不应被偷渡成游戏规则。

数学复现样例：R=105、I=0、n=1 时，非生命中间值约 125.49999237，五星值 175；I=60 时为 209。生命在同样两个 I 下分别为 348、400。这些是源码计算结果。作者还把 R105 的 175、209 等称为实测结果，本项目尚无对应原始证据。

与 Showdown 非生命写法 `round((round(1.1×(R+3×t))+10)×n)+50` 的关系：若令 `I=6t`，未取整的代数系数相同；**浮点存储与取整位置不完全相同，不能据代数等价宣称所有整数输出相同**。例如 R105、t=0、中性时，直接十进制公式会得到 176，而 Arena 单精度口径为 175。

## 伤害参考：两个口径必须分开

来源：[Arena 计算说明](https://rocoarena.com/calculation-notes) 与 [Showdown 计算原理](https://roco-showdown.com/battle-use-guide)。Arena 引用[毒酱只玩毒的视频](https://www.bilibili.com/video/BV1K4GP6sEmx/)，本次未能取得该视频内容。

设 A、D 为**明确输入的攻击/防御面板**，P 为已经处理变威力和技能威力效果的值，M 为本次明确适用的倍率；对 60 级单段普通伤害：

```text
Arena 说明口径：floor(round_JS(A × P × M × 37/41) / D)
Showdown 口径：Q = round_JS(P × M)
              floor(round_JS(A × Q × 37/41) / D)
```

Showdown 还给出等级系数 `(0.45×L+10)/41`；本报告没有证实 Arena 在其他等级采用该扩展。其网页示例本系为 1.25；该值也得到 [Rocoduel 自述](https://rocoduel.com/zh/how-we-calculate) 的支持，但仍属于社区计算来源。

两种口径存在可区分实验：A=100、D=102、P=75、M=1.25 时，Showdown 路径为 83，Arena 路径为 82。该例是人工构造的数学判别条件，不是本项目实战记录。

Showdown 对攻防等级使用方向分组：攻击提升与防御降低位于分子，攻击降低与防御提升位于分母。该说明将特性、固定威力、同类百分比、显示威力、最终伤害分成不同阶段。缺少上下文时应要求调用者输入明确有效威力和倍率，不能自动假设全部为 1，更不能同时输入已修正面板又重复乘同一增益。

## 上线与校准边界

- 两种参考结果可用于解释差异、设计真实对战试验；未经后续核验，不接入平台默认结算或隐藏配置似然，其不确定性不应悄悄隐藏在整数结果里。
- 本次没有证明游戏的完整浮点精度、所有等级/星级、个体加点总量、双属性抵消顺序、减伤及连击最终取整、伤害下限、随机波动、护盾和逐击触发。
- 不把复制/借用技能当原配招证据，不把伤害造成的属性变化回写到本次攻击之前，不把未知特性作为无效果。
- 下一步真值采集优先挑取两种公式输出不同的条件，保存双方完整配置、实际面板、技能/特性/印记/天气、版本和原始截图或视频。先逐样本比较，再扩大到复杂回合。
- 当前已核实的是资料和公开程序的计算方式；正式训练的 `mechanics_verified` 必须继续为 false。

原始响应 SHA256、抓取时间、关键表达式位置与 BWIKI 修订信息见 `data/reference/mechanics-20261025/evidence.json`。为避免复制整份第三方前端，只保存哈希及短数学表达式；临时下载文件不属于项目实现。

本次重取 Arena 属性脚本，SHA-256 与原记录一致。另核查固定提交的 Roco Sandbox，只有旧版社区实现，没有取得本项目当前版本真实对局证据；具体差异、许可证及来源见 [来源复核](verification/formula-source-review-20261025.md)。独立测试的对象是明确表达式的 Python/JavaScript 运算，而非真实客户端伤害。

修正本报告初版对术语 1002、1004、1008 的转述：原始词条未写“每层”；不能把层数线性叠加当成这些词条已直接证明的事实。表格已改为原词条可支持的范围，并保留逐层行为、基数和取整待核实。

候选接口：`arena_stat60` 使用原始资质数值、两处 float32 转换及五星常量；`showdown_non_hp_stat60` 使用展示资质数值和公开的非生命面板表达式，不补造生命公式。两者都显式接收性格倍率，不从未完成的资质推断或旧性格表填值。`arena_documented_damage60` 和 `showdown_documented_damage60` 只返回 60 级单击的名义伤害，不是实际扣血，不做生命削顶、最低伤害、额外最终倍率、技能或特性判断。两者均明确先算 `37/41` 系数；完整中间值和运算顺序随结果保留，不能随意做代数重排并假定浮点边界相同。
