# 实时战斗接入

更新：2026-10-28。进度总览：[PROJECT_STATUS.md](PROJECT_STATUS.md)。历史逐轮原文与证据引用保存在清理归档的同名文件中。

## 启动

协议采集来自vendor/rkpp，版权归原作者。需要Npcap、管理员权限及项目专用.venv-rkpp。

1. 运行 `python -m lab.server --port 8766`。
2. 打开洛克PVP.exe，点击“启动抓包”并允许UAC。
3. key_hits=0时重新登录/重启游戏，抓到0x1002建连密钥。旧密钥只在对应连接仍存活时尝试复用。
4. 在APP中查看密钥命中、包数、业务记录和日志。
5. 点击“显示HUD”，可用APP按钮或Ctrl+Alt+Q关闭。详见 [APP说明](DESKTOP_APP.md)。

中继默认127.0.0.1:8765，工作台8766。PowerShell5.1启动脚本需UTF-8 BOM。

## 已有链路

Npcap → rkpp → relay /latest → LiveBattleFeed → BattleTracker → HUD快照。结构化对局读取content；live_bridge仍提供摘要事件面板。

| opcode | 用途 |
|---|---|
| 0x1316 | 入场、队伍、技能槽和面板 |
| 0x131A | 回合状态、在场与换人补充 |
| 0x1322 | 选择同步 |
| 0x1324 | 施法、伤害、生命/能量结果、BUFF与其他同步 |
| 0x1314 | 回合结束 |
| 0x132C | 终局 |

处理了64位字符串、有符号变化、技能槽与被动槽分离、技能ID归一化、base_conf_id形态识别、按pet_id隔离技能观测。归属不明成员进入pending_pets。

接口：/api/live/status、/api/live/events、/api/live/battle、/api/hud/snapshot、/api/hud/revision。

中继断开时保留最近对局；HUD明确标离线历史快照、数据年龄与终局。最近快照不是当前在线的证明。

## 数值与未完成项

当前生命读取battle_inside_pet_info.battle_attr[25]，最大生命仍为[1]；与客户端PetUtils.GetHP/GetMaxHP及rkpp原始字段解析一致。观战开局、换人、补位和回合完整快照均接入，不能以最大生命代替观战者尚未见到的当前生命。缺少当前生命时保留已知值，首次中途出现则未知；不会借当前生命倒推一个假的最大生命。

PVP采用60级五星口径，性格增益1.2/减益0.9，默认本系1.25。用户提供的魔力猫六维样本符合当前面板公式，属于局部证据。

HUD正算将报文含性格基础面板与当前状态层数、已审特性和天气查询组合；印记触发损血与愿力强化预览单列，固定连击展示每段伤害×次数。应对版观测归并普通技能，不把已发生的应对威力用于下一手普通估计。按需求排除防御选择、应对增伤、条件连击、首领化及光合治愈；未覆盖规则或缺少条件明确提示。伤害反推按结算前的独立局面复用同一正算查询；实际应对结算使用其原始变体，dam_type保留为技能属性编码。仍受精度、减伤等未覆盖条件影响，不能把候选冒充确定真值。

我方attribute_info的break_enhance_enum、talent_add_value、talent已接入三项加点直读，保留来源。未下发加点的一侧先用已知面板，再用直接伤害枚举恰好三项；双方HUD均展示。正反算在有证据的浮点边界上保留精度候选，已知协议六维不被模型改写。验证样本为data/reference/live-panel-20261029.json中的6只我方、36维，不代表全版本公式校准。

非PVP真实星级没有可靠字段，雷达标签显示0–5星可能范围，不再把等级推测当作确定星级。五星以上“系别极化”语义未明确，尚不计算。
