# 悬浮HUD

更新：2026-10-29。当前进度见 [PROJECT_STATUS.md](PROJECT_STATUS.md)，采集见 [RKPP_LIVE.md](RKPP_LIVE.md)。历史说明已在清理ZIP中保留。

打开项目根目录洛克PVP.exe，点击“显示HUD”，默认打开我方、敌方及屏幕顶部回合记录三个Electron透明置顶窗口，分别加载 `/hud-duel?side=my`、`?side=enemy` 与 `?side=history`。内部开发启动脚本仍保留，日常无需BAT。

- Ctrl+Alt+Q：关闭HUD；若热键无效，在APP中点击“关闭HUD”。
- Ctrl+Alt+L：切换穿透；Ctrl+Alt+F：将三块面板恢复到默认位置。
- 三块面板顶栏均可拖动；×关闭HUD。再次显示可使用APP中的“显示HUD”。
- APP模式不创建额外HUD托盘图标，显示/关闭通过APP及现有热键完成。

可显示生命、能量、形态、性格方向、六维雷达、BUFF、己方配招、对方已观测技能、当前状态伤害估计与替补。应对版与普通版合并技能槽；固定连击显示单段伤害×次数。四槽下方展示印记触发/回合损血，以及携带愿力强化时的血脉愿力预览。中继离线会保留旧局面并标明历史快照与时间，终局显示已结束。真实星级未知时雷达标签显示0–5星可能范围，五星以上未计算。

敌方栏最下方“技能查询”可展开查看当前具体形态的BWIKI学习范围，搜索名称、系别或描述，并显示血脉、等级、阶段等学习条件；它与已观测四槽相互独立，不将候选标成已携带。第一次展开按需读取，之后使用本地页面缓存，切换精灵按对应形态查询。

顶部回合记录显示本次采集到的整局技能、换人、每段伤害及结束结果；伤害超过实际扣血时同时标明两者。新记录自动跟随到底部，向上浏览时保留滚动位置；新局清空旧局。中途接入显示观测起始回合，不伪造此前历史。

吹火按50+20×此前使用次数计算，迫近攻击同机制按90+45×次数计算；换人保留、开新局重置，当前攻击取本次使用之前的次数。缺少完整采集历史时明确阻断，不默认为零次。复制、借用、重复槽位等未知历史基线不能当作已经校准。

魔能爆读取当前剩余能量预估；实际已发生伤害的反推读取施放前冻结能量，避免扣费后误读成0。现用带来源的0..10档候选表，缺能量或超出档位不代填；悬停可读未全档校准提示。

首领化、萌化优先采用服务器当前形态ID，图标、名称、技能槽和数据一起更新；服务器已退化的形态不再被重复退一次。被动有cur_passive_skill覆盖时保留该覆盖。顶部记录同步显示已确认的形态变化。

伤害预览组合已知攻防状态、特性、天气与已接入的动态威力；有明确配置的应对分支在同一行分两档显示“未应对/应对”，分别给出单值或范围及每段×次数，不预测对方必定被应对。生命、状态层数、能量和槽位取当前观测；未知输入保持范围或具体原因，不补零。防御选择、其他条件追加连击、首领化和光合治愈仍不纳入。悬停伤害查看依据和未覆盖提示，规则与取整未完成全量实战校准。

技能伤害预览只显示普通伤害，不展示暴击预估。最低估计总伤害严格大于目标正余血时，标红“秒！”，仅最大值足够时不显示。双方已确定的加点仅以雷达属性文字标黄，未知数值显示范围；性格在名字下方，改写方向鼠标悬停可见。不再展示性格组合、三项列表、种族值说明、下发面板/模型核对及逐条伤害依据，后台证据保留。

HUD每300毫秒读取后台发布缓存，单次请求、不重叠，未变化时只取确认响应；HTTP读取不运行反推。订阅线程发现积压时连续取后续页；暂时状态超时不会再被控制台显示为“等待游戏建连”。上一回合一致的推断不会因下一条冲突观测被清空，跨局/明确配置变更仍按来源隔离。图标有本地缓存、原始资源ID映射与两次失败重试。

观战中已受伤的精灵入场按报文当前生命显示，例如火羽1/354显示1%，不默认354/354。缺少当前生命时保留本局已知值；首次中途发现且字段缺失显示未知条纹，不冒充满血或倒下。

完整且唯一的exec_index用于还原表现分组中的真实执行顺序，伤害与反推均取命中时的状态，避免提前驱散增益或回合后留下已清除状态。缺少有效序号的旧报文仍保留原顺序；不将数组分组位置解释为已验证结算顺序。

数据来自 `/api/hud/snapshot`，工作台也可发布。`/hud-pro` 保留第三方原版HUD与桥接。HUD含协议额外字段，不能直接替代RL公开观测。伤害估计尚未完成全机制校准。
