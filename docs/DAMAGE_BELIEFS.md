# 根据伤害观测更新候选配置

该模块只计算给定候选、先验及伤害预测下的条件概率，不自行产生热门配置、完整资质或真实游戏伤害分布。阵容码仍不能恢复完整六维资质，不能用零或满值补齐后冒充已知配置。尚未训练或校准的模型不能通过此接口获得“已验证”资格。

## 两种明确的似然

旧 `damage` 事件使用每个候选的闭区间 `[minimum, maximum]`，假设其中整数伤害等概率。这是显式的均匀模型，不能据此声称游戏伤害随机性也是均匀的。

新 `damage_distribution` 事件接受离散分布，允许不同伤害的概率不同。例如 `POST /api/belief` 的事件部分为：

```json
{
  "event": {
    "id": "round-1-hit",
    "kind": "damage_distribution",
    "damage": 10,
    "measurement_tolerance": 0,
    "prediction_source": {"id": "explicit-experiment", "snapshot_id": "20261025T013619+0800"},
    "predictions": {
      "a": [{"damage": 10, "probability": 0.1}, {"damage": 20, "probability": 0.9}],
      "b": [{"damage": 10, "probability": 0.9}, {"damage": 20, "probability": 0.1}]
    }
  }
}
```

请求还须包含显式 `candidates`，或先前响应中的完整 `belief`。在上述构造例中，若 a/b 的先验权重为 3:1，观察伤害 10 后，后验分别为 25% 与 75%。这只是算术回归，不是游戏实测。

每个原始候选都必须给出非空分布，包括当前权重为零者。伤害必须是非负整数，概率有限且在 0～1 内；重复伤害结果报错，不合并。概率和须在绝对误差 `1e-12` 内为 1，不接受任意权重后悄悄归一化。显式测量容差通过累计观测区间内的概率质量处理，默认零容差；不添加其他噪声或测量假设。

这里的伤害须与实际观测量一致。显示伤害、生命实际减少、过量伤害和合计多段伤害不能不加区分地混用；本模块不推断这种转换。双方连续观测须由调用者针对新的共同局面重新提供每个候选的分布，不能把一次旧预测用于所有后续回合。

## 来源与恢复

离散预测来源只接受 `id`、`snapshot_id` 两个非空字段，它们是调用者声明，不是已认证的公式。一个推断存档中的离散事件不能混用不同声明快照。旧均匀区间事件没有这一来源记录，不能借后来的来源声明为它们补认证。返回值始终注明 `prediction_verified=false`，正式训练也不由此开启。

后端 `belief` 使用 schema 3，保存原始候选先验和完整事件（包括分布、来源与容差），恢复时重新计算后验。兼容 schema 1、2 的旧事件；旧版本标记下出现新离散事件会拒绝。相同事件 ID 和相同证据不重复计数，改写证据复用旧 ID 会报错。若所有候选都无法解释观测，保留最后一致的后验及冲突事件，等待纠正输入或模型后重放，不自动重置先验。

网页保存的是展示摘要，不是后端可重放的 `belief`。摘要保留声明来源、均匀/离散模型类别及精度提示；如需以后重算，应另外保留 API 响应的完整 `belief`。普通对战页仍不会自动生成分布或根据伤害调用未经校准的预测器。

## 极小概率

内部使用对数概率累计证据。显示浮点数不足以表达的正概率，不会变成永久排除；后续相反证据仍能恢复。真正的零先验或零似然仍是零。`underflowed_candidate_ids` 明确保留暂时无法显示的候选标识，此时显示 100% 不能理解为绝对确定。未知槽位的极小概率候选仍会阻止完整槽位结论；网页也不会据显示摘要把它们当成已排除。
