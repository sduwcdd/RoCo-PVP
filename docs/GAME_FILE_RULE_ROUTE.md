## 已交付

`lab/game_rule_candidates.py` 复用固定版本解析器，从原始字段结构、二进制配置和本地化重新解析八表，逐表校验原提取哈希与可读 JSON 一致性。新增负偏移边界检查，不修改保留的旧工具。结果保存缺失、显式零、空数组、参数位置、重复引用和原始槽位。

候选图包含 **17,578 条原始记录**和 **1,988 条 SKILL_CONF 组件候选**，后者同 ID 对应 BWIKI **579 个技能、246 个特性**，其余记录的玩法适用性未确认。所有节点附原表、记录哈希、来源版本、提取路径；技能组件分为费用、伤害、目标、顺序、冷却、结果引用，未知参数保持不透明，不猜测可执行效果。

3,445 个非零技能结果引用全部存在：1,457 个指向效果、1,988 个指向状态；4,603 个非零状态基础引用全部存在。额外保留 3,041 个缺少 ID 的 `{}` 技能结果项及一个显式零的状态基础引用。不能因非零引用闭合，就说整个规则已经可执行。

效果配置中的 81 类处理类型、基础状态中的 150 类处理类型已绑定到代码使用的枚举族。`effect_order`、`buffbase_order` 在这些调用处表示处理类别，不是先后顺序。映射附代码哈希和行号。`cast_moment` 与 `trigger_type` 尚未完成字段到执行枚举的绑定，继续分域保存。

## 魔镜的层数说明

用户解释魔镜一次施加 **5 层**，每层魔防降低 **10%**，并类比魔法增效。原话含“原因应该是”，完整原文与结构化数值保存在 [语义证据](verification/game-config-semantics-20261025.json) 的 `user_clarifications`，来源标记为用户说明、文件映射待定位。

建模须区分：基础状态的每层效果、一次行动施加的层数、当前层数、层数上限、衰减及清除条件。用户说明解释了魔镜两处描述差异；不将所有状态的加成乘区或叠加算法一并视为确认。

文件链为魔镜 7170280 → 状态 20010080 → 基础状态 2001008。所读补丁技能结果子结构只含 effect_id/cast_moment；已读客户端复制下发的 stack，并显示 buff_stack_change，尚未找到生成五层的处理位置。补充基础包分析已确认魔法增效7020630历史配置为7层，但基础包没有魔镜7170280和另一条魔法增效7880001，不能复制历史层数给它们。当前线上行为仍待核验。

## 文件研究仍需解决的事项

1. 最高数字补丁的候选选择可复核，实际挂载顺序和在线配置覆盖尚未确认。
2. 序列化缺失与显式零不同；原生读取器是否物化默认值未确认。Lua getter 对 nil/false 使用调用方默认值，不能直接推断二进制缺字段的最终值。
3. 能耗和冷却会从同步数据更新；当前读到的伤害函数消费已算结果。显示拆段的 ceil 不能作为伤害公式。
4. 通知队列先入先出仅证明客户端播放顺序；尚未确定权威触发顺序、嵌套效果、死亡与入场结算。
5. 处理类型命名有证据，绝大多数效果/基础状态的参数位置、单位、目标、条件仍需实际处理器绑定。不能仅凭命名把负数解释成已实现的扣能效果。

## 后续迁移顺序

先沿处理类型集中追踪属性状态、加减层、能量改变与迅捷技能调用，记录每个参数的代码使用点。随后将已确认语义转换为既有组件，并先验证单机制边界、组合、事件顺序和状态隔离；每批审查通过后才显式发布新版本。保留旧规则回归与来源，不做逐技能整句特判。无法可靠执行的组件返回具体缺口；实验假设与用户说明分别留档。
