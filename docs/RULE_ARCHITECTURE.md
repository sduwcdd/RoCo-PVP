# 可组合规则架构与渐进迁移

## 当前源码结论

改造前 `skill_programs.py` 在运行时由 `BwikiRuleset` 调用，以完整句式匹配生成 operations；`effect_runtime.py` 已有可复用基础效果与原子片段，但缺少独立配置边界。`action_runtime.py` 和 `switch_runtime.py` 各自调用效果解释器，后者还把已选迅捷限定为单个 damage 操作。状态、印记和行动阶段规则已有来源约束，不能因迁移丢弃。

本次冻结 v6 自然语言编译器为离线候选/历史回归工具，不增加整句分支。既有程序作为迁移输入，保留 v1–v6、原始快照、阵容与网页记录。运行时从发布配置加载；来源变化必须重新离线审查，不能自动重新解析并执行。

## 分层格式与执行边界

规则配置的身份为 `rule_id`、快照和来源哈希。每个组件携带自身 evidence（快照、记录哈希、原文、模块、链接、迁移依据）和 uncertainties，不将实验假设写回来源。`program` 保留历史兼容头部，**不保存另一份 operations**；operations 必须由 components 生成，避免两份规则漂移。

```json
{
  "id": "effect:1",
  "kind": "effect",
  "effect": "energy.reduce",
  "target": "opponent",
  "params": {"amount": {"expr": {"const": 3}}},
  "when": {"compare": "lte", "left": {"read": {"target": "opponent", "field": "energy"}}, "right": {"const": 5}},
  "evidence": {"...": "绑定来源，不在此示例中捏造证据"},
  "uncertainties": ["低能量边界和判定时点需显式实验策略"]
}
```

这是格式示意，不是新增 BWIKI 技能。现阶段目标为 self/opponent；全队、随机、指定后备、印记持有者等选择器须后续实现后才能通过校验。效果包括原有伤害、固定连击、条件伤害、治疗、返能、扣能、属性项、状态和防御计划；结构化防御计划不等于已有防御执行。

表达式支持整数、有理数、明确资源读取和有界 add/sub/mul/min/max；条件支持比较及 all/any/not。不使用 eval，不读取任意对象路径，不用浮点近似或默认取整。amount/power/hits 可使用表达式，结果需要整数，否则阻断并要求取整策略。条件与表达式在明确 `after_payment_before_each_component_experiment` 策略下读取每个组件执行前的当前状态，费用必须显式提供且只支付一次。

四类语义必须分开：

| 概念 | 表达位置 | 不允许的替代 |
|---|---|---|
| 先手度 | 行动排序修正 `constraints.priority` | 不等于已经先于对方行动 |
| 应对成功 | 行动类别匹配及应对事件 `response_success` | 不等于普通 resource compare 或任意加先手度 |
| 先手／后手条件 | 实际行动位置、已发生历史 `turn_order_condition` | 不能从速度或先手度直接推断 |
| 主动换人入场 | `entry_trigger` 和已选技能使用事件 | 不在手动技能使用时再追加一次攻击 |

`constraints` 还保留 duration、cooldown、execution_limits 的独立位置；当前未迁移项显式 `not_migrated`。第一阶段不伪造它们的完成值。后续新增模式必须同时增加 schema 校验、通用运行组件和机制测试，而不是给技能 ID 添分支。

## 事件与效果执行

`event_scheduler.dispatch_events` 是确定性的通用调度器，订阅来自技能／特性／状态／印记均使用同一格式与处理接口。事件带来源、event_id、parent_id、depth 和 emitted_by；多订阅缺少唯一顺序则阻断，不按 ID 或注册顺序猜测真实先后。

子事件 FIFO、每个订阅执行次数、事件／深度／调用预算均明确为实验政策。达到订阅次数上限记录 skip；超出全局预算或处理异常返回原状态与诊断轨迹，不返回部分已提交效果。诊断轨迹不是实际游戏战斗日志。回调必须无外部副作用，状态事务无法撤销外部操作。

手动行动及主动换人选中迅捷后均调用 `skill_execution.execute_skill`。迅捷只负责原四槽顺序、最终费用和可负担性选择；选择后不再限制为单个 damage，也没有技能名称/ID分支。基础效果由原运行器复用，保留原有免疫、费用、状态、来源与力竭阻断。

`execute_rule` 消费带条件和表达式的组件数据，静态配置通过兼容路径保持旧行为；动态配置逐组件执行并原子回滚。低层传入的实验配置不因语法正确就变成 BWIKI 事实；生产加载仍须通过配置 manifest、来源指纹和全记录静态校验。兼容适配器遇条件/表达式会拒绝，不能删除条件后降级。

**边界**：当前实际接入通用队列的是技能使用事件。通用调度的嵌套 trait/status/mark 组合已用合成规则测试，但实际 246 个特性及全部状态/印记触发链尚未迁移；旧状态结算仍是显式片段。它们是下一阶段工作，不能宣称已完成完整事件引擎或完整回合。

## 四种独立能力与本次批量迁移

- 描述完整结构化：172／579 技能，0／246 特性。
- 隔离组件类型支持：上述技能中 168 个；仍要求各自实验策略和必要的伤害解析器，不表示全部输入可执行。
- 完整对战可执行：0；防御、力竭、费用不足后续等整体语义仍缺失。
- 实战已校准：0；没有实战真值，不将构造检查算作校准。

本次迁移全部 825 条配置，已有结构化操作涉及 damage 132、固定连击 18、返能 14、属性变化 13、状态 9、条件伤害 3、治疗 3、防御计划 1、扣能 1 个技能（有重叠），包括 22 个多效果技能。收益是这些类别统一成为来源绑定的数据，并共享执行与事件边界，**不是新增 172 个已还原技能**。

## 后续迁移顺序

1. 本阶段：全量审计、配置加载/校验、表达式与条件、共同技能入口、事件预算与来源链；保留旧输出并逐项回归。
2. 修正生命周期：统一实例 ID、施加来源、目标、作用域、叠加/替换、到期、驱散、冷却；先批量审查属性/威力/费用修正，明确不同作用域，不从词法命中直接发布。
3. 将应对、状态、印记和特性接入事件订阅；根据来源建立显式顺序偏序，存在不可比较触发时返回具体阻断，不默选总顺序。
4. 历史条件、随机目标、全队选择、复制/进化/魔力与力竭链；真正特殊机制注册专用处理并注明原因、来源和执行限制。
5. 版本数值策略与实战校准独立接入，不阻止前述架构/机制实现；胜利奖励训练继续由完整性与校准门槛限制。

测试优先覆盖基础边界、组合、顺序冲突、嵌套循环、来源冲突、隔离和确定性；全配置静态校验与代表性已知问题回归永久保留。事务回滚是实验接口的失败约定，绝不代表游戏撤销已发生行动。

## 阶段属性与仍保留的边界

`phase-config-1` 保存全部579技能的固有迅捷完整元数据及直接蓄力分类。运行时不再扫描技能描述中的迅捷词或蓄力前缀；离线复现器保留原分类逻辑和来源检查。全部迅捷输出逐字段一致（6真、572假、1未知），直接蓄力仍为5个，不扩展技能实际结算。

老印记工具仍用术语原文前缀建立术语索引；它仅用于已有印记分类/保留逻辑，没有新增效果执行。这部分连同印记生命周期将在下一机制阶段迁移，当前并未声称整个项目完全没有文本分类。

带when/expr的配置通过`execution_program`携带完整native_rule进入共同执行器，兼容`rule_to_program`继续明确拒绝这种降级。双行动预检使用`preflight_skill`，执行时读取保留的动态组件。原静态配置保留旧接口字段与结果，动态规则只修改数据即可改变目标、常数、资源条件和受支持表达式；添加新的效果类型仍须实现通用组件。

原生规则的外层身份、来源和空兼容operations必须与内部rule.program严格一致，防止执行结果归到错误技能。联合行动计划遇到原生配置中的防御/应对组件会明确阻断：付款后组件when不能用于推断行动前的应对成功或抹去应对信息。纯隔离组件实验的false分支可以不执行，但不据此宣称联合排序已确定。
