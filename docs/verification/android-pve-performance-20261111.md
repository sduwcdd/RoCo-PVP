# Android 0.8 模式与解析性能

## 本轮修改

保留0.7完整战况功能作为默认PVP模式，新增PVE模式，选择保存在APP私有目录。PVE只展示当前敌方精灵、性格与增减方向、体重、声音参数及奖牌提示，不运行六维反推、特性绑定和伤害预测，也不加载PVP的HUD页面。

PVE复用同一解密、封装验证、协议字段表和图鉴。通过明确的字段投影读取必要元数据和入场、换人、力竭、结束事件，未选字段不递归展开。所选字段仍检查线格式、边界、类型及嵌套深度。元数据解码独立计数，不冒充完整业务解码。

性能剖析发现上行封装识别反复调用`Data.get_proto_schema()`，回放中377次读取约耗时8.4秒。封装识别和PVE投影现统一复用`rkpp_analysis._ensure_loaded()`已有的进程字段表缓存，固定资源包在本次后端生命周期内保持一致。APP重启后重新加载并验证资源。图鉴也复用现有只读`runtime_catalog()`。PVP程序初始化延迟至真正收到战斗通知时。

新入场先清除旧卡片，换人依据报文位置和精灵身份，目标未识别、力竭、战斗结束及分析暂停时清除显示。Python或原生镜像队列积压时显示同步提示，避免把旧卡片当作当前目标。PVE界面与原生状态检查周期为250毫秒，HTTP轮询保持单请求。模式切换后清空旧观测，须等待下一场入场通知。

本轮未改动游戏数据转发、伤害公式、技能效果及随机规则。PVE的外观格式和奖牌范围判断沿用现有实现，奖牌预测与边界提示继续标记。

## 当前样本验证

输入为用户提供的`roco-mobile-protocol07.zip`。原始报文及含个人信息的完整结果仅保存在本地忽略目录。将全部1006个有序输入事件突发交给从APK提取的编译后端，共处理1247个协议帧，未暂停、无解密错误，结束时队列为0。

| 路径 | 本机回放耗时 | 结果 |
| --- | --- | --- |
| 0.7 PVP | 13.4498秒 | 基准最终战况 |
| 0.8 PVP | 4.2870秒 | 最终BattleTracker快照SHA-256与基准相同 |
| 0.8 PVE | 1.0721秒 | 12条元数据通知，覆盖3次入场，9次有效显示 |

PVP与PVE各以独立进程运行。计时涵盖突发字节解析和队列处理，不含APP启动。不同路径的程序初始化成本不同，不能将上述倍率直接当作真机显示延迟。0.8后端初始化在本机约2.1秒。PVE卡片处理最大45.7毫秒，未初始化PVP规则程序。

另一次定向核对将12条战斗通知同时交给投影和完整字段解码，所有可见元数据结果相同。模式API正常请求、非法枚举、跨来源拒绝、模式持久化及头像资源读取通过。PVE切换、断联和队列积压的旧卡片清除有针对性检查。

验证原始记录位于`artifacts/app/mobile-07-pvp-replay.json`、`mobile-08-pvp-final.json`、`mobile-08-pve-final.json`和`mobile-08-pve-parity.json`。临时剖析及冒烟脚本完成后删除。APK验证和源码身份见`mobile/build/android-0.8-verification.json`，该文件属于本机打包产物。

## 边界

尚无本次0.8在用户Redmi手机上的安装与延迟数据，未作真机界面验收。样本为大世界遇敌，不能据此确认手机PVP 6v6。PVE在对局中途切换模式时等待下次明确入场，不从缺失历史猜测当前精灵。iOS采集仍维持既有未接通状态。
