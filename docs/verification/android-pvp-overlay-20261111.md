# Android 0.9 横屏PVP悬浮层

## 实现

使用三个独立`TYPE_APPLICATION_OVERLAY`窗口。我方左上、敌方右上，回合记录顶部居中。每栏标题点按收起或展开、拖动移动，收起状态分别保存。横屏默认窗口互不重叠，左右正文高度为屏幕高度减去边距和底部64dp预留，历史高度最多为屏幕36%或192dp。

透明WebView加载同源`pvp-panel.html?side=my|enemy|history`，内部直接复用Windows HUD，不改动数据解析、伤害规则及后端轮询。包装页只注入手机viewport、紧凑样式和自然高度观察。正文变化时32毫秒合并一次高度报告，Native进行像素换算和屏幕边界限制。

窗口使用`FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCH_MODAL`，只有自身矩形范围参与触摸命中。收起后将真实窗口缩至标题大小，并卸载WebView内容。未放置覆盖整屏的透明母窗口。初次加载从小尺寸等待卡片开始，收到内容高度后展开，防止空白窗口预先占满高度。窗口整体alpha为0.78，原HUD与背景继续半透明。

切换PVE/PVP模式后原生窗口类型随现有服务状态检查更新，横竖屏变化时重建布局，关闭采集时统一销毁三个窗口。PVE原有单窗和轻量字段处理保留。

## 验证

- Node运行真实页面脚本的51项针对性检查通过，包括现有HUD、移动界面及新增包装器5项检查。覆盖side白名单、DOM变化、高度去重、观察器清理、无新增轮询和既有HUD行为。
- 使用实际`PvpOverlay.measure`的编译Java方法检查4种屏幕尺寸、3种像素密度、3种栏位及2种展开状态，共72组。尺寸均在界内，横屏展开栏互不重叠，左右底部预留成立，收起高度为32dp。
- 浏览器使用明确标记的构造数据查看三栏布局，包含六维、四槽和回合信息。该检查验证Web内容呈现，不能替代Android原生窗口验收。
- Android构建与APK签名校验记录保存在本机`mobile/build/android-0.9-verification.json`。打包后核对资源、Python字节码及原生源码身份，临时冒烟脚本与编译输入删除。
