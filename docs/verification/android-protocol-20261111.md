# Android 0.6 协议兼容核对

## 实录依据

用户提供0.5导出的ZIP，在本地读取和回放。压缩包及完整业务内容保持私密。

- ZIP SHA-256为`bcda97ae6b2f88d37c38af02e3d1c1fe1fe09d2035816db57c1b0932d35e8d33`。
- 实录来源为`mobile-20261111-internal-05`，采集源码身份与修复前本地一致。
- 游戏版本为`1.112.0.116`，414个有序字节事件，2份连接握手，471个BE21协议帧。
- 样本达到分析失败后的15秒窗口，采集未报告缺口，回放末尾没有未完成帧。

## 原因与改动

上行布局的外层值为0，操作码高16位为`0x0078`，随后2字节回显低16位操作码。偏移30开始为正文，尾部沿用现有TSF4G校验。该组合已在本份实录核对，其他布局维持既有路径。

登录请求`0x0101`的`cli_info`及其`ext_info`存在当前字段表未收录的字段。多种合法请求正文为空。`0x0149`实录为客户端发出的通知，静态名称表推断方向为服务端；方向冲突显式记录，未重写原始表。部分新操作码尚无字段定义，保留原文和未知状态。

已观测布局允许空正文及线格式正确的未知字段，保留原始payload。已知字段仍校验类型、嵌套结构及UTF-8，检查字段号范围、uint64边界、完整消费、外层长度、序号和尾标。未知布局继续要求完全匹配字段表。涉及未解决战斗字段时保留阻断。
