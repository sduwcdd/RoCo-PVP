# 组合规则与统一调度独立复核（2026-10-25）

结论：所检查的第一阶段机制复用路径在明确实验约束下未发现尚未修复的阻断问题。这不是完整对战或实战一致性评估。

## 复核范围

检查 `skill_execution` 的手动/入场共用入口、组合组件顺序、付款与条件求值，`rule_expressions` 的精确有理数与受限资源读取，以及事件调度器的来源、父子链、订阅次数与循环保护。对 action_runtime、switch_runtime 的调用点逐项检查：两者均通过 execute_skill 执行已选中的技能效果，入场不再只允许单条普通 damage 操作，仍保留来源触发条件和第一可用原槽选择；不支持的完整技能由共用流程拒绝，不能跳到后一个技能。

该阶段接通的是通用 skill.use 执行路径。技能、特性、状态与印记可以复用同一调度接口，但真实特性/状态/印记触发链尚未因此接入。独立测试中的四种订阅是合成示例，不能算为真实机制覆盖。

## 已发现并修复的问题

1. 动态组件外层付款后删除 resolved_energy_cost，使条件伤害组件再次预检时错误阻断。修复后外层只付款一次，各组件声明零追加费用，同时保留 component_sequence_paid_cost；条件读取实际当前能量，组件内部零付款事件不重复输出。
2. 统一入口回调闭包曾引用调用者的原始 program/context。伤害回调可修改原始 operations，把未经预检的返能效果加到本次执行。修复后入口先取得自有深副本，原始对象的后续修改不能污染本次结果。
3. 动态路径曾可把缺失付款证据默认为零，绕过条件伤害原有的显式费用要求。修复后即使费用为零也必须显式声明，缺失时在回调前阻断。

以上均用独立标准输入脚本复现并验证修复。入口篡改探针最终只有一次 energy.pay 和一次 damage；动态条件伤害正确扣除一次费用。没有创建临时脚本。

## 验证

- 原生配置接入前的相关六组回归：scheduler、expression、skill_execution、action_runtime、switch_runtime、switch_integration，共 **103 项通过，63.078 秒**。这是当时修订的结果，不冒充后续接口调整后的同次全量运行。
- 前一轮三个新组件组 **32 项通过，2.056 秒**；与最终六组重叠，不累计为独立测试数。
- 另执行 **343 组构造组合**：自身能量 0～6 × 对手能量 0～6 × 费用 0～6，196 组提交，147 组费用不足阻断。合成配置包含先降魔防、再根据付款后自身能量判定是否扣对手能量，并由 min/max 和资源读取计算扣除量。检查实际状态、两个组件顺序、条件读取、仅一次付款、请求/实际减少边界、输入不变与训练禁用标记。
- 缺失动态费用的单独探针确认未调用伤害函数，返回原状态和空战斗事件。
- 事件测试涵盖嵌套 FIFO、显式订阅顺序、未知/冲突顺序阻断、执行次数 skip 记录、事件/深度/调用预算、异常回滚、结果副本与确定性。trace 使用 event_id、parent_id、emitted_by 和原来源；这些是诊断轨迹，不是失败后仍提交的战斗事件。

组合表达式使用整数或精确分数，不接受代码字符串、浮点或布尔数值；需要整数效果参数时分数结果明确阻断，未默认取整。先手度、应对成功、先手/后手条件和入场事件没有借用普通资源谓词彼此替代。

## 边界与待核实

低层 execute_rule 允许明确实验配置；语法通过不代表配置与 BWIKI 原文语义相符。正式来源绑定须经过配置包与快照校验。构造修改配置不计入真实技能还原数量。FIFO、描述顺序、每组件读取时点和低能量截零均为显式实验政策，真实游戏触发顺序、费用不足后的行动处理、完整特性/状态/印记链仍待实现或核验。事务回滚表示不提交失败的模拟结果，绝不表示游戏会撤销已发生的行动。外部回调应为纯函数，其外部副作用无法回滚。

## 原生配置执行路径追加复核

后续增加 execution_program 原生封装：动态组件保持完整 native_rule，旧 rule_to_program 仍拒绝把条件或表达式抹平成普通 operations。execute_skill 路由原生规则到 execute_rule；联合行动用 preflight_skill 检查两种表示。已检查 false when 的魔镜扣能组件穿过真实联合行动调用路径仍不执行，付款与另一个魔防组件保留。

追加审查发现并修复两项边界：

1. 原生外壳的 game_id/source_hash 曾可与内部 rule.program 不一致。低层直接调用仍成功；测试注入提供者后，联合行动事件记录的是伪造外壳来源。正常离线加载器原本生成一致外壳，此问题属于低层/扩展提供者边界。修复后 _native_rule 要求外壳与内部程序、空旧 operations、native_rule 严格一致，execute_skill 和 preflight_skill 均检查；伪造 ID、来源、非空旧操作或额外字段全部拒绝。
2. 联合计划原来只从旧 operations 提取防御应对。原生 operations 为空时，带 false when 的防御组件会丢失应对排序，并且可绕过原防御执行阻断。修复后联合计划遇到原生 defense.plan 组件直接返回 response ordering unresolved。资源条件不能冒充应对成功事件；低层纯片段可以跳过 false 分支，但不能据此推断真实联合顺序。

两个原生边界定向回归 **2 项通过，2.736 秒**。另用独立标准输入探针确认伪造外壳在两入口阻断，以及 false 防御在计划/联合执行两处均阻断、返回原局面和空事件。没有重跑或冒充整组全量；主代理另记录广泛回归与最后定向运行。以下哈希更新为上述最后修复后的文件。
