## 已交付

- `lab/core_magic_runtime.py`：104001光合治愈、104003闪焰爆发和既有104004节流术共用显式策略入口。初始化仅允许新鲜第1回合；库存、战内次数、技能CD独立记账，均由来源行派生并校验；无字段补0。104001/3的BATTLE_ITEM_CONF是重新用已校验parser从34行二进制中读取，并非照搬104004的99。
- 光合治愈：立即恢复，然后施放回合及后续两个回合末各恢复最大HP的15%；向下取整、裁剪缺血量、不可复活，离场清除BUFF20173890。持续计时、百分比基数/取整是显式实验策略。

- `lab/forced_trait_runtime.py`：警惕200092、奔波命200105、防过载保护200165、安可200290绑定完整源行和形态特性；只有明确启用已知trait_policy时生效。警惕在回合开始绑定选择，即使动作被跳过仍能于回合末检查；奔波命只为防御技能安排回合末脱离；保护行动后触发；安可光系技能后安排回合末返场。

## 尚未能可靠执行的事项

1. **104002愿力强化**：2126002→2129001对应buffbase_order126/129仍只有BFT_O_TWEENTYSIX/TWEENTYNINE占位名；触发、目标、时长没有可靠语义。首槽愿力冲击的血脉/等级/服务端返回skill_id解析亦未完成，不能省略附加BUFF只改槽。
2. **104007进化之力**：223组形态映射已保存；HP/面板/技能/特性/血脉/信物条件的完整迁移未给出。客户端BattleRoundSelectAction.RefreshByServer直接OverwriteByServer完整PetInfo，不证明本地有可复用变换算法。
3. **104005遁逃术**：Skill7010050→Effect1067001(order67)及描述均确认“逃离”；PVP能否使用、逃离终局归属/得分/训练师资源没有本地可靠规则。未把逃离虚构为胜利或投降。
4. **104006噩梦纠缠**：引用Effect20010440和20010441未出现在当前可用EFFECT_CONF；替换池范围、污染血脉23资格、槽位/重复规则、10%全属性含HP的迁移也没有完整已审resolver。不能只接随机替槽而漏掉引用操作。
5. **104008测试道具**：道具描述“消耗1魔力，恢复10能量”，但映射Skill7010013为NPC光合治愈；保留冲突，未按名称猜测。
6. **104009唤名/104010召唤亚瑟**：Skill7010075/7010076描述仍为“文本待补充”，依赖场景或NPC状态，未冒充PVP能力。
7. **104011–104033 NPC变体**：分别涉及特定NPC资格与不同target_type/effect参数；同名不构成与玩家1/3/4的安全别名。逐行保存来源和具体缺失效果，不自动替换到玩家版。
8. **其他强制换人完整技能**：如防御应对、双方同时脱离、继承增益、指定入场状态、下个入场减伤等，基础component已经可用，但整技能仍需要完整条件和后续效果适配，不能把局部可切槽标成全技能可用。

## 复活的已确认与待核实

- BWIKI特性200230“不朽”和patch0/3及后续已提取SKILL_CONF均写“力竭4回合后复活”；base archive写3回合。这是**基础包与补丁差异**，不能称patch3仍为3回合。
- 当前patch3特性引用Effect20730130（cast_moment26、11）及1004117（cast_moment11）；20730130未出现在已提取可用EFFECT_CONF，1004117仅提供移除BUFF20990030。
- 客户端`BattleDataCenter.DoWrite`先WriteSyncData，再对BPT_REVIVE发送BattlePetRevive(target_id)；`WritePetSyncInfo`消费hp_result、energy_result、revive_round、revive_rounds，说明结果由同步包提供，没有在该脚本计算复活HP/能量。
- 因而剩余待核实：4回合从力竭时还是后续回合何时开始计数；复活HP和能量值；状态/蓄力/增益/复活次数清理；后备复活与入场选择；入场触发；终局与训练师魔力已耗尽时的优先级。没有给这些缺字段补0或满血。
