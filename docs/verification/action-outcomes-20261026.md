# 已提交动作中断与直接击败归因（2026-10-26）

`lab/action_outcome_runtime.py`提供来源绑定的三个打断技能程序，以及已提交动作的致死直接攻击证明。来源配置为`data/rules/reviewed-action-outcomes-1.json`；200141的条件额外魔力损耗纳入既有`victory_rules.py`来源账本。

阻断7020520、地刺7080130、斩断7140090均有完整BWIKI文本、安装基础技能→应对变体→1003001的链。Enum明确`ET_INTERRUPT=3`；术语1011为“使敌方本次无法释放对应技能”，1015明确应对状态必定先手。程序仍通过普通执行器进行各自75魔伤/90物伤/70物伤，再对尚未提交的对应状态技能登记取消marker。

marker精确绑定回合、目标成员、槽和skill ID。执行前`consume_interrupt`逐项匹配当前成员/携带槽：换人或槽内技能改变不会继承旧取消；已提交对手动作不回滚。同一marker重复消费仍返回cancelled但无重复事件。被取消的释放不执行、费用为0；若为待释放蓄力，清除该charge避免下回合成为过期记录，这是明确研究策略，不声称原始游戏已确认蓄力保留边界。

`record_committed_action`须在普通技能成功写回之后、换人或KO统计之前调用。只从同一已提交源动作的`damage/damage.hit`、物理/魔法、实际整数before>0/after=0及相等HP损失建立证明，绑定原攻击者和受害者的member/form/trait、技能、source hash、token和即将统计的KO occurrence。毒、烧伤、印记事件不会因为敌方当前在场就变成直接击杀。原攻击者后来换下也不丢失已证明的来源。

200141按证明中的角色条件分别产生额外损耗1：原攻击者有该特性则受害方额外损耗1；受害者有该特性且直接被敌方击败则自己额外损耗1。两方各有该特性时，在基础损耗1上各自+1得到请求3；与诈死基础0可组成请求1。额外项及原证明均保存在魔力loss source账本并重放核对，不以当前位置推定。旧occurrence证明不能用于复活后的新倒下；缺少直接证明时仍明确阻断，未把未知间接击败原因当成不触发或触发。
