# 出手顺序与速度推断

日期：2026-11-21。
Windows目标版本：1.1.15。
安卓目标版本：0.16.4，版本号22。

## 原有能力

原实现提供速度候选范围。
候选来自种族值、等级与性格。
资质候选沿用现有三项加点模型。
原实现没有采集出手顺序约束。

## 本轮实现

新增 `lab/live_speed.py`。
模块收集同回合的双方普通行动。
双方通常分两份报文施放。
跨包使用 `perform_cmd.seq_num`。
包内使用 `perform_info.exec_index`。
缺失或冲突的序号不作推断。
纯环境包不参与主行动排序。
相同主行动报文不会重复采信。

主行动同时检查两层类型。
外层 `perform_info.type` 必须为1。
内层 `skill_cast.type` 必须为1。
外层时机必须为0。
外层必须是分组头且引用为0。
普通技能还须通过技能类别检查。

排序前冻结双方的公开状态。
敌方未观测技能不进入冻结状态。
冻结状态与后续报文保持隔离。
双方必须各有一次主行动。
双方技能先手度必须相同。
先手度采用原生静态档位。
不再重复叠加已包含的静态修正。
可见天气修正使用现有查询。
特殊先手条件未核实时不采信。

换人、变形和应对回合会被排除。
额外释放和共鸣回合会被排除。
中断施放也不会产生速度约束。
顺序未完整观测时不推断。
两次行动之间修正变化时不推断。
后续出现额外行动时撤回本轮证据。
之前回合的有效证据仍保留。

己方 `battle_attr[6]` 已含速度修正。
本轮直接读取该值。
不重复叠加速度状态或天气。
未知敌方速度复用现有属性查询。
当前支持已核对的速度固值修正。
百分比修正的内部精度仍待核实。
敌方含此类未知修正时不采信顺序。

未识别状态会阻断本轮采信。
派生状态按原生引用逐层检查。
优先、迅捷及未知子引用会阻断。
状态20170880单独绑定四级来源摘要。
其BUFFBASE编号17引用EFFECT1085006。
该EFFECT再引用技能7060220。
不混用不同表内的编号85。
任一级来源变化都会撤销放行。

## 配置筛选与界面

速度证据接入 `infer_configuration`。
伤害证据与速度证据共同筛选。
等级、形态及数据快照继续绑定。
不会另写速度资质或性格公式。
不会覆盖游戏直接下发的配置。
不会为候选配置赋予虚构概率。

敌方先出手时保留“大于或等于”。
敌方后出手时保留“小于或等于”。
单次顺序不能排除同速随机。
只有所有相容候选一致时才标确定。
例如同种精灵速度超过中性上限后，
仍须检查单独性格加成的可行性。
不能直接把先手认作双速度配置。

雷达图直接显示缩窄后的区间。
确定速度加点后沿用黄色文字。
确定速度性格后沿用向上箭头。
速度文字悬停显示已用顺序次数。
换回同一只精灵时继续沿用证据。
新对局会重置证据。
