# 行动阶段规则独立审查

日期：2026-10-25。范围：`lab/switch_rules.py`、`lab/action_rules.py`、`lab/turn_plan.py`。审查没有修改实现；依据当前 BWIKI 快照 `20261025T013619+0800`、Terms 修订 7078 与 [规则发现记录](bwiki-rule-discovery-20261025.md)。这不是实战校准，新增实战样本为 0。

## 已核对的边界

- 同回合入场免疫仅用于脱离、返场、紧急脱离；没有扩大为主动换人免疫。力竭下场独立于普通离场事件。
- 蓄力期间主动取消未知；释放准备就绪只返回许可，不能清除蓄力记录或执行技能。审查发现的提前清除问题已由实现者修复，记录保留到后续执行器提交释放。
- 蓄力准备使用独立阶段，不伪装成攻击释放参加应对。费用明确为调用方提供的当前行动阶段实验输入，不从未来释放费用推断准备费用。
- 迅捷只在主动换人入场计划中调用，保持四槽与空槽位置；未知的前置候选不被跳过。缺少入场元数据时返回待核实。
- 印记继承与正负两个槽位有来源；覆盖、叠加和上限未冒充已验证规则。调用方实验假设保留来源标注。
- 双应对成功、相同先手度、换人与技能、未知技能语义的排序不采样，不给出 50% 概率；同先手度也没有仅凭速度决定顺序。
- 联合计划基于同一份回合前状态，要求双方行动同时提交；任一方输入无效时不暴露另一方部分计划。计划不改变输入状态，也不执行资源结算、伤害或胜负。

## 检查证据

独立运行 `tests.test_switch_rules` 与 `tests.test_action_rules`：36 项通过。随后独立运行协调器当时的 `tests.test_turn_plan`：11 项通过；主实现者在此后增加测试，其最终数量由整体验收记录提供，不能将早先结果冒充最新完整套件结果。

额外使用真实快照构造的临时内存反例均通过：

1. 规划前后输入状态完全一致，修改返回计划的嵌套内容不影响原状态。
2. 第二方选中空技能槽时，结果阻断且双方计划均不暴露。
3. 第四槽蓄力技能保留槽位，准备阶段排序待核实，不作为普通攻击释放。
4. 下一回合蓄力释放就绪时，原始蓄力状态仍保留，要求未来执行器提交释放。

最后只读复核了新增迅捷逐槽绑定、未知修正传递与当前阶段费用说明，未发现新的阻断问题。审查探针通过标准输入执行，没有遗留临时冒烟脚本。
