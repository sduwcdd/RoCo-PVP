## 2. 核心魔法接入细节

### 愿力强化 104002 → 首槽替换

数据来源：解包 `SKILL_CONF` 中 `7700001–7700019` 共 19 条记录，除 `skill_result[5].effect_id`（1031536…1031554）外字段完全一致：
`dam_para=[80]`、`energy_cost=[2]`、`skill_priority=5`、`target_type=1`、`cd_round=[0,0]`；`7700006` 名称标为「废弃」。

因此只落地**公共面板参数**（威力 80 / 能耗 2 / 优先级 5），不指定具体 `skill_id`，并在记录里显式写 `variant_resolved:false`。
变体到系别的归属未解析——不猜。

界面：选 104002 后出现提示条（`核心魔法效果` 区块）显示替换事实与原首槽名；技能下拉里首槽选项追加 `→ 愿力冲击（本回合替换）`；能量按 2 费而非原技能费计算。

记录结构（行动层新增字段）：
```json
"first_slot_replaced": {
  "name": "愿力冲击", "power": 80, "energy": 2, "priority": 5,
  "variant_resolved": false, "user_note": false, "original_first_slot": 7
}
```
`actionLabel` 摘要追加 `/ 首槽替换为 愿力冲击（威力 80 · 能耗 2）`。

### 进化之力 104007 → 形态选择

- 选中 104007 后出现"进化形态（本场战斗）"下拉，候选由 `evolutionCandidates(formId)` 生成：同 `number` 且名称互相包含的形态。迪莫 `3004`（编号 001）→ `5025 圣光迪莫 / 5026 圣草迪莫 / 5027 圣火迪莫 / 5028 圣水迪莫`。
- 选定写入 `evolution_target_form_id`；校验：该字段只能随 `core_magic_id=104007` 出现（`进化形态只能随进化之力记录`）。
- 摘要追加 `/ 进化形态 圣光迪莫`。

### 迪莫例外（用户口径，未经游戏文件核对）

`CORE_MAGIC_USER_NOTES` 记录了 `{form_ids:[3004], magic_id:104007, rule:"also_replace_first_slot", source:"user_statement", verified:false}`：
迪莫使用进化之力时，除形态进化外同步把首槽替换为愿力冲击（记录里 `first_slot_replaced.user_note=true`，界面文案带"用户口径例外，未经游戏文件核对"）。

这是按用户陈述落地的行为，不是从解包规则验证出的结论。
