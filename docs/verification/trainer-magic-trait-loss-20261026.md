# 特性修改训练师魔力损耗组件（2026-10-26）

`lab/victory_rules.py`保留`initialize_victory/validate_victory/reconcile_knockouts/terminal`接口，新增来源配置`data/rules/reviewed-trainer-magic-loss-1.json`，不修改特性主模块。

## 原始依据与范围

- 诈死200081：BWIKI和安装文本均为“自己力竭时，少损失1点魔力”。21040020→2104002，opcode104、参数`[1]`。组件在基础损耗1上减1，得到请求损耗0。
- 御驾亲征280019：文本明确“棋契陛下大幅提升种族资质，力竭时扣除4魔力”。21040012含3个2104001，opcode104、每项参数`[-1]`。实现的是显式扣4魔力组件，保留重复base原行；不声称opcode通用符号语义已完整还原，也不把资质调整判成完成。
- Enum记录opcode104为`BFT_O_FOUR`；这是原始名称，不人为改写成一个未出现的“修改魔力”枚举名。
- 200141付给恶魔的赎价要求“击败敌方精灵”或“被敌方精灵击败”。普通HP活→零观测没有杀手/直接击败证据。因此，死者或对方当前活动成员涉及该特性时，明确报未适配并阻断账本提交；不从当前场上位置推断杀手，也不对毒、烧伤等倒下擅自增扣。

配置绑定BWIKI快照、对应形态→特性映射及各行hash、安装技能/BUFF/BASE表和Enum文件hash。使用已启用的trait_policy、member trait_id与形态来源核对；无trait_policy的旧状态继续按原规则每次倒下请求损耗1。

## 次数与实际损耗分开记账

旧账本仍按原`knockouts`次数校验。启用新组件后增加`victory.loss_components`，保存配置hash、旧账本基线、逐次倒下事件。事件记录发生回合、side/member、occurrence、请求损耗、实际损耗、魔力before/after、胜点增量及特性行/形态来源。

`knockouts`继续记录每个已观察到的活→零边沿；诈死损耗0仍计一次倒下。实际魔力损耗为请求值与剩余魔力的较小者；御驾请求4但剩3时只扣3并给对方3胜点。复活先被观察到才重新武装下一次倒下。同一次重复reconcile不重复计数或扣损耗。

校验器从旧counts/magic基线逐个重放有来源的事件，独立核对次数、损耗、胜点与occurrence；不再错误地要求带诈死/御驾的魔力必等于4减总倒下次数。旧基线只保留已验证的历史事实，不虚构各次旧倒下的时间或扣损耗顺序。观察阶段对ledger使用副本事务，后续出现无归因的200141时不会留下前几个成员已扣、后几个未扣的半账本。

## 验证与限制

5项定向用例通过，0.938秒：诈死两次真实倒下/零损耗；御驾请求4与余额3封顶；传统默认1及旧账本迁移；重复观察幂等；原复活后第二次倒下回归；200141无归因阻断和来源hash篡改拒绝。另在同一御驾用例补充完整余额4时实际扣4、只计1次倒下的断言，该单项重跑通过，0.559秒。

这只是来源绑定的损耗组件。没有修改御驾的种族资质，也没有实现200141的直接击败证据接口、复活行为或实时服务端归因。已有同时耗尽、50回合和队伍耗尽裁定限制维持原样；没有实战校准或训练资格声明。
