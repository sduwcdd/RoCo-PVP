# Android 0.15 上行前缀兼容

## 当前依据

开发前将本机干净的`35481dd`检出快进同步至GitHub主分支`0d19f48`，复用0.14已有的应用内更新、国内更新源、图鉴头像及PVE身份修复。

用户提供`roco-mobile-protocol (3).zip`。包内记录设备为Xiaomi 2604FRK1EC、Android 17/API37，游戏报告版本仍为1.112.0.116，APP构建为`mobile-20261114-154650`。因此只能确认当前流量格式发生变化，无法仅由该包确认游戏安装包版本号已经更新。

129个有序输入事件组成207个协议帧。握手和转发成功，23条上行业务帧因`ok_unparsed`未识别。它们均使用`0x006Exxxx`原始操作码，低16位回显、外层长度、序号、保留字和尾部有效；现有实现只识别实录验证过的`0x73`、`0x78`、`0x7A`前缀。

## 修复与验证

在共享解析器已有手机封装入口中增加经过本次实录验证的`0x6E`。保存原始操作码，不解释前缀的版本或厂商含义。未知前缀继续走原有严格字段准入；非法线格式、错误字段类型、截断嵌套、回显与序号冲突仍拒绝。

- 本次样本修复后207帧全部处理，包括190条业务帧和17条控制帧；未识别和未消费字节均为0。
- 旧`0x78`实录1247帧回归通过，未识别0。该文件是本机实际保留的历史实录。
- 45项Python定向检查通过，包含新前缀及原有`0x73`、`0x78`、`0x7A`的校验边界。
- 从新APK提取的编译后端分别运行PVE和PVP，均处理全部207帧，队列归零且分析无错误。由于样本没有战斗通知，PVE保持等待并清空敌方卡片，PVP保持未识别对局。
- APK包名、15 / 0.15-internal版本、131个Python模块及加密资源一致性检查通过，实际证书与本机私钥对应的`f62169dd`摘要一致。安装包位于`mobile/build/roco-mobile-android-internal-0.15.apk`，本机验证记录为`mobile/build/android-0.15-verification.json`。

原始会话、设备诊断和取证日志仅保留在用户提供路径及Git忽略目录。本机结构报告为`artifacts/app/mobile-20261120-before.json`、`mobile-20261120-after.json`及`mobile-20261120-previous78.json`。临时取证和冒烟脚本验证完成后删除。

## 发布与签名

用户明确要求本机使用现有签名生成0.15，并将私钥位置告知另一开发设备。本机私钥位于D盘工具环境，证书SHA-256为`f62169ddc3fd0df6d55ec550717e31692ec4ebce6d0d0a5fb1e43e1178758354`，与仓库记录的另一设备0.14证书`b6a6896a62a5d84a377b064e745f4d492d551e89272db10b26894aa2289b19f2`不同。Android签名校验与应用更新的签名检查继续保留。相同本机签名可覆盖，另一签名需备份数据后重新安装并统一后续签名。

## 待核实

本次样本没有战斗入场或回合通知，只能验证当前登录及业务解析恢复。手机安装后的PVE/PVP显示仍待真实对局反馈。本机0.15安装包尚未发布远端更新源。
