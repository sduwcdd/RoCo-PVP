# Android 0.14 图鉴图片与 PVE 身份

## 图鉴图片

图鉴的 `portrait()` 原先直接请求 BWIKI 的外部图片网址，没有使用 APP 已携带的本地图片。现改为优先请求同源 `/roco-pet-avatars-id/{游戏ID}.png`，本地缺失时再尝试原始图片网址，两者失败时显示文字占位。

当前 BWIKI 快照有 662 个形态，其中 38 个缺少本地图片。本次从快照记录的 BWIKI 图片地址补齐这 38 个 PNG，并替换了文件内容损坏的喵喵图片，共下载 39 张、16,483,254 字节。下载检查 HTTPS 来源、大小上限和 PNG 文件头。原始网址、文件摘要与长度保存在 `web/assets/roco/manifest.json` 的 `bwiki_portraits`，原有资源来源记录保留。当前 662 个形态均有本地图片。

## PVE 身份

在本机保存的入场解码报文中复现了“性格可见，精灵未识别”。例如 `base_conf_id=9006`、`conf_id=1646` 的敌方下发名称为“龙棋士”，同时下发了性格，但该 ID 未收录在 BWIKI 和现有原生形态表。

原 PVE 精简解码没有保留 `PetData.name` 字节字段，显示层只查 BWIKI 及实际上没有下发的 `conf_name`，因此丢失了报文已有的名称。另有 `9004`“金月陨星”可由既有原生形态表查询，原 PVE 路径也没有使用此兼容查询。

现保留名称字段，按 BWIKI 形态、既有来源绑定的原生形态、报文名称依次显示。沿用桌面现有的 UTF-8 十六进制名称解码。保留原始 `formId`，用 `identitySource` 区分 `BWIKI`、`historical_external`、`reported_name` 和 `unresolved`。不会将报文昵称反推为另一只精灵或替换原始 ID。完全无名称依据时明确显示未收录 ID。

这里的复现依据是本机保存的解码对战记录。上一轮 `roco-mobile-protocol (2).zip` 的 67 个帧没有对战通知，不能将它描述为本次 PVE 入场验证的来源。

## 定向验证

- 10 项 PVE 与本地图片检查通过，覆盖名称的实际协议字段编码和精简解码、未知 BWIKI ID、原生形态查询、已知形态优先、部分更新保留、换人和新对局隔离。
- 11 项移动界面检查通过，新增图鉴本地图片优先、网络备用及文字占位检查。
- 662 张当前图鉴图片全部通过 PNG 文件头、分块 CRC 和 IEND 结束块检查。
- 从最终 APK 提取编译后端及资源在本机运行，图鉴页和喵喵、千棘海针、奔波鼠图片接口均返回 200，图片摘要与源文件一致。PVE 名称字段编码后通过 APK 的精简解码和状态接口，保存的“龙棋士”“金月陨星”入场解码报文也正确显示名称、原始 ID、身份来源和性格。记录位于 `mobile/build/android-0.14-runtime.json`，该验证使用电脑运行 APK 后端。
- 安卓版本提升为 14 / 0.14-internal，沿用原签名及国内更新流程。
- 重新打包消除了增量 APK 中未被引用的旧数据，最终大小为 181,636,662 字节。全部 67 个 ZIP 成员内容与上述回放版本一致，重新检查了签名与版本。最终 SHA-256 为 `dfebcdb7ed82e4c17e8de2ec5d67a831bddb96edc687339c93fdcc1fef97b3c9`。

真机安装后的 PVE 和图鉴展示仍需用户复测。本次不改伤害或对战规则。
