# 当前对战机制缺口核查

2026-10-25。基于当前源码、现有解包表和客户端反编译代码的只读审计；未修改战斗规则。本轮重新运行了默认模拟器配置扫描和四个构造回合。不是游戏实战校准。

## 当前统计口径

- 当前 BWIKI：579 个技能、246 个特性。
- 使用 `lab.simulation._programs` 和网页默认设置：183 个技能被标记可用、396 个标记未支持。183 是界面/程序准入数量，不是完整对战可执行数量，更不是还原率。
- 183 的优先来源标签：162 BWIKI、11 历史补丁效果、9 天气、1 纯伤害蓄力。这是最终覆盖后的互斥标签，不可再与旧版本支持量相加。
- 已发布通用配置的静态统计仍为172个描述结构化、168个局部组件支持。它不包含所有新加载覆盖，特性静态统计为0也不能否认另行接入的5个天气特性。
- 完整逐技能结果、源码快照哈希、词法候选列表和实际阻断结果：[JSON](mechanism-gap-current-20261025.json)。

## 可从现有文件继续推进的部分

- `EFFECT_CONF.effect_order`、`BUFFBASE_CONF.buffbase_order`已与各自枚举绑定，技能和状态引用关系可读。缺的是大部分处理器的参数解释和执行，不是需要用户重新提供整个图鉴。
- `BUFF_CONF`已有`add_max`、`cover_id`、`buff_groupsigns`、`buff_group_reduce`、`is_clean_when_rest`。可沿这些字段继续实现通用状态管理。
- 基础包及补丁2的效果引用含`result_target_type/success_rate/buff_level_rule/buff_group_level`；补丁3简化引用只余`effect_id/cast_moment`。已确认力量增效10层、魔镜5层，不能再将其描述差异列成无解问题。
- 技能替换、层数变更、CD、插入技能等处理器编号已有记录；`SKILL_CONF`内也有特性技能及其结果引用链。
- 实际文件适配器目前只覆盖极窄的确定目标、确定概率、无CD即时属性/能量效果；它并未通用执行全部EFFECT/BUFFBASE图。

## 已有可执行研究方案、但尚未恢复权威逻辑的部分

1. **伤害与面板公式**：当前采用命名的社区候选；真实属性叠加阶段、同系倍率、多段威力、取整仍未恢复。`BattleDataCenter`读取服务器下发的`damage_result/hp_change/hp_result`并拆分展示，不能把动画取整当战斗公式。
2. **事件域与顺序**：例如天气状态BASE2017123的`trigger_type=7`与旧`client_trigger_type=[15]`并存，两个域不能按同一数字解释。通用调度器有来源、嵌套和循环保护，但真实全部事件订阅尚未接入。
3. **资源适用版本**：安装目录保留多版本，不能把历史完整字段自动拼成已确认线上版本；挂载优先级和在线覆盖未证实。
4. **天气细节**：沙暴费用取整、天气开启当回合计数、引电消层/离场、冻结参数50等仍是有名字的研究策略或待解释项。不能因此把已经接通的四天气整体列为未实现。

## 对完整辅助与训练目标的影响

隐藏配置的离散贝叶斯更新组件已存在，但仍依赖外部候选先验与版本化伤害似然；名称检索不等于热门使用概率。RL文件提供接口、仅胜利奖励与校验门槛，没有把当前不完整试战包装成可正式训练的完整环境。建议顺序：先修魔力胜负与能力误标，再完成防御应对、统一状态/印记/修正生命周期，之后批量接入特性、动态技能及核心魔法。
