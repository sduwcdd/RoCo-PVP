# Android 0.16 变动上行头字段

## 故障证据与修正依据

用户提供`roco-mobile-protocol (5).zip`，设备报告Xiaomi 2604FRK1EC、Android 17/API37，APP为`mobile-20261120-internal-15`，游戏报告版本仍为1.112.0.116。104段有序字节回放得到154帧，其中23条上行未识别、114条业务帧成功、17条控制帧，剩余字节为0。

这23条记录的原始操作码字均为`0x0070xxxx`，低16位与紧邻回显相同。前一份同机型、同报告游戏版本记录使用`0x006Exxxx`，历史记录还出现`0x0073xxxx`、`0x0078xxxx`和`0x007Axxxx`。各记录外层长度、序号、保留字和填充格式一致。将上部字做成固定白名单的假设已导致重复失败，当前证据不足以赋予该字版本、厂商或会话编号含义。

共享解析器现通过已验证的外层封装和低16位操作码回显识别该布局，完整保留32位原值。上部字作为不透明字段，不参与取值白名单判断。所选布局继续检查已知字段类型、嵌套边界、字符串编码、非法变长整数及完整线格式；未知字段和缺失字段表保持明确标记。回显不匹配的其他布局仍走原有完整字段表准入。

社区[rocom-parse协议资料](https://github.com/whoisnian/rocom-parse/blob/master/docs/protocol.md)同样仅从上行偏移6读取16位操作码，并将前面的字节标为未知。本轮具体封装识别以用户当前多份实录的逐字节核对为主，该社区资料作为补充参考。

## 实现和回归

- 删除手机封装上部字固定集合，以完整封装和操作码回显识别布局。
- 诊断补充完整候选操作码和上部字，继续仅保存结构字段。
- 新增跨不透明字段取值的结构测试，同时检查非法线格式、字段类型、嵌套和原始值保留。旧测试中只因未列入白名单而拒绝的断言改为真正的回显冲突断言。
- 47项Python定向检查通过。
- 当前154帧全部通过，包含137条业务帧和17条控制帧；未识别0、剩余字节0。
- 上份207帧和历史1247帧实录通过，逐帧方向、命令、序号、操作码、状态及字段表匹配结果与0.15记录相同。
- 从新APK提取的编译后端分别运行PVE和PVP，均处理全部154帧，队列归零，无分析错误；由于没有战斗通知，保持等待对局。

原始流量、诊断及离线结构报告保留在本机忽略目录，未作为公开测试夹具。报告位于`artifacts/app/mobile-20261120-05-fixed.json`、`mobile-16-previous6e.json`、`mobile-16-previous78.json`和`mobile-16-apk-{pve,pvp}.json`。临时取证和冒烟脚本完成后删除。

## 构建与剩余限制

默认版本为16 / 0.16-internal，沿用0.15本机签名。APK位于`mobile/build/roco-mobile-android-internal-0.16.apk`，构建身份为`mobile-20261120-internal-16`。签名、资源及字节码核对记录保存于本机`mobile/build/android-0.16-verification.json`。

样本没有战斗入场或回合通知，手机安装后的PVE/PVP显示仍待实测。上部字的具体游戏含义仍未确认，本实现保留原值。后续若封装结构或字段类型发生变化，现有检查仍会明确阻断。
