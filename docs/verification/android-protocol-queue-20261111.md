# Android 0.7 队列与吞吐修复

## 证据

用户返回0.6协议样本，ZIP SHA-256为`05f2575b588585f8bf3ffdb6ed0a71fcbdd10c0dc078be85e2d4487c342bb859`。私密原始文件未纳入源码。460个有序字节事件组成573个BE21帧，其中542个业务帧、31个控制帧及1次握手。导出记录首先报告解析队列满，镜像错误和转发错误均为0。

完整离线解析另外发现6帧上行空请求的外层[12:16]值为46384，旧实现据0.5样本将其限制为0或1，造成未识别。该字段含义仍不确定，当前保留原值；已确认手机格式由0x0078操作码前缀、低16位回显及长度/序号/尾标等共同确认。

## 实现

- 复用共享解析器增加逐次调用的payload过滤入口，默认完整解析，无全局开关。手机版延后当前BattleTracker不消费的已知非战斗字段解码，保留完整密文采样和payload。战斗及未知消息仍完整解码。
- 延后消息仍校验封装、完整顶层线格式和边界，不视为字段表解码成功，单独计数；非法报文继续暂停分析。
- 解析队列上限改为1024段，并以8 MiB字节预算约束。完成处理时释放字节计数，仍保持输入顺序及超限保护。
- 保留变动头字段原值，继续阻断未确认布局及已知字段类型冲突。
- 未修改VPN转发、游戏报文、伤害公式、技能或随机规则。

| 检查 | 结果 |

| 从0.6 APK加载，突发提交新样本 | 第130个事件附近触发128段队列限制 |
| 从0.7 APK加载，突发提交新样本 | 460个事件全部接收，573帧全部处理，队列归零 |

| 同APK完整解码模式 | 16.833秒 |
| 同APK优化模式 | 6.308秒 |
| 最终BattleTracker快照 | 两模式SHA-256相同 |
| Python定向检查 | 32项通过 |

两个解码模式使用独立进程，从同一APK加载代码和资源；比较包含解析、战况更新及最终快照构建。时间来自本机并行回放，不能替代手机性能测量。原始比较结果保存于被Git忽略的`artifacts/app/mobile-burst-07-full.json`及`mobile-burst-07-filtered.json`。

新样本的4条战斗通知包括进场、回合开始、回合结束和战斗结束。解析所得模式为大世界，双方队伍数为6和1。该结果不构成手机PVP 6v6验收。0.7仍需用户在真机安装后使用验证。
