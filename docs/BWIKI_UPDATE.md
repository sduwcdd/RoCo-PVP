# BWIKI 版本维护

用户发现游戏更新后发起维护。当前数值、精灵、技能池、性格及属性表以 BWIKI 数据模块为准。现有解包文件保留为历史机制证据，实战修正规则继续复用。BWIKI 更新可能晚于游戏更新，维护时需核对其 `current_version` 和页面修订时间。

## 维护流程

1. 退出本项目 APP 和源码工作台服务。
2. 在项目根目录运行下方命令。先查询基础数据及公开赛季模块的修订编号，只下载变化的模块。未变化模块复用已校验原文。所有模块均无变化时直接结束。
3. 脚本规范化最新数据，生成与本次来源匹配的规则文件，并同步已核查组件的版本绑定。保留原始修订、哈希和旧规则证据。完整描述使用既有离线编译器，运行时继续执行结构化配置。
4. 数值变化若涉及组件内固化的威力、费用，或者描述、机制、术语等语义变化，脚本列出具体字段/技能并停止激活。维护者在同次任务内继续适配相关组件、更新来源依据并进行定向验证，再通过 `--resume` 完成启用。无法确定的机制保留具体原因。无需另行生成候选发行版或差异报告。
5. 全部绑定迁移完成后，以独立进程验证规则、阶段、HUD 数据和现有机制加载。通过后直接切换活动快照。异常时恢复源码、配置与原指针，中断事务可在下次执行脚本时恢复。
6. 重启源码 APP 加载整套新数据。服务进程固定使用启动时的快照，其缓存与数据保持同一版本。维护脚本和服务之间使用文件锁，避免并发改写。

```powershell
.venv-rkpp/Scripts/python.exe scripts/snapshot_bwiki.py
# 处理脚本指出的组件适配问题后，复用本次已下载的修订
.venv-rkpp/Scripts/python.exe scripts/snapshot_bwiki.py --resume <本次快照ID>
```

如果下载期间 BWIKI 又出现新修订，重新执行首条命令获取一致版本。上次下载原文继续保留来源记录。

S5 使用 BWIKI 的 `Pets/SeasonData` 入口和公开赛季清单，按网站源码顺序合并精灵、技能、特性及辅助数据。元组仅作为静态数据解码，加载器源码绑定已核对的哈希。基础图鉴数量与赛季新增形态数量分别校验。网站展示策略暂时关闭当前赛季时停止更新。原文、清单及模块缓存属于增量更新所需来源文件。

## 数据优先级

`lab/catalog_store.py` 是网页及 HUD 的共同快照入口。`battle_data` 的公开查询优先使用该快照中的名称、属性、阶段、特性、种族值、技能威力和能耗。字段未知时保持未知。解包原始字典继续用于原生效果引用和既有来源哈希校验，回退数据标记 `historical_external`。

网页试战只有在历史技能的静态威力、类型、能耗与当前 BWIKI 一致时才采用该历史实现。否则使用当前来源规则或返回对应阻断，避免历史表覆盖当前数值。

## 安装版发布

数据更新后重新构建不加密的朋友测试安装包，再通过现有 APP 更新渠道分发。维护命令只更新本地源码与数据。

```powershell
.venv-release/Scripts/python.exe scripts/build_updatable.py --version <新版本号> --id <新安装包ID>
```

安装包保留来源清单、资源哈希和后端身份；数据变化时重建后端，不复用旧安装包冒充新数据。确认发布后继续使用 `scripts/publish_app_update.py`，用户可在 APP 内更新。

旧安装版尚不包含本轮改动。新技能描述可以被编译、组件能够执行、实战已经校准仍分别记录。
