# BWIKI 规则核心迁移进度

本层是完整六精灵对战引擎的在建组成部分。未提供完整回合、正式训练或实战建议，不将历史引擎当作当前版本的默认结算器。

## 数据与程序

`lab/ruleset.py` 按游戏 ID 提取 BWIKI 当前值，保留快照、模块修订和哈希。属性倍率直接使用防守形态的完整 `relation_key` 表，不把双属性相乘；例如罗隐的武系弱点为 3 倍。未知属性、未知 ID、缺失组合与重复记录均明确拒绝。检索到的记录为副本，不能反向污染规则状态。

`lab/skill_programs.py` 将可完整解释的技能描述编译为结构化操作，包括普通伤害、固定连击、固定能量回复、百分比生命回复、明确属性百分比修正、固定状态赋予和防御计划。v2 支持明确无条件复合语句，例如毒针的攻击后施毒、丰收的攻击后回复生命；v3 支持完整的“造成物伤/魔伤，N连击。”描述。只有整个描述匹配才产生操作；未知附加句、额外说明、类别冲突均拒绝，不能截掉复杂条件后退回普通伤害。

当前 579 技能中 172 个描述可编译，407 个未支持；246 个特性全部明确未实现。v2 比 v1 新增 11 个描述，v3 增加 18 个固定连击描述，v4 再增加 3 个能量条件描述，v5 增加翼击的完整迅捷攻击描述，v6 增加魔镜的降魔防与能量减少；原 v4 的 170 个程序除编译器版本外保持一致。这里的“可编译”只说明描述已有完整结构化表达，不代表整个技能已经可执行或实战已验证。术语依赖、描述顺序与真实事件顺序的差别仍单独记录。所有程序保持 `executable=false`、`real_game_verified=false`。

生成命令：`python scripts/compile_bwiki_rules.py`。当前产物在 `data/rules/<snapshot_id>/bwiki-declarative-6.json`，包含全部技能、特性及各自来源；v1、v2、v3、v4、v5 原文件仍保留。相同编译器版本的不同产物不会静默覆盖，需升级版本并保留旧证据。

## 基础效果运行器

`lab/effect_runtime.py` 的 `execute_effects` 只运行明确隔离的技能效果实验。状态、面板、资源上限及实验策略由调用者显式提供；属性修正保留有理数项，不推导面板公式。实际伤害只能由调用者提供的实验解析器返回，当前没有默认伤害公式。

所有操作先做依赖检查。缺失公式、未支持效果、快照不一致或实验策略未指定时，返回原状态与空事件；显式能量支付也不会留下部分修改。成功事件记录完整程序哈希、快照和未校准状态，四个技能槽包括空槽原样保留。

生命回复另需显式 `hp_policy`：`percentage_basis` 选择 `declared_max_hp` 或 `current_hp`，`rounding` 选择 `exact`、`floor`、`ceil` 或 `half_up`，`cap` 明确为 `clamp_to_declared_max`。这些全部是调用者选择的实验参数，不是当前游戏真值。内部使用精确分数；`exact` 遇到小数会拒绝并回滚。事件分别保留未取整请求、取整后的请求、实际回复与溢出，不把满血溢出悄悄丢弃。

复合效果逐项读取更新后的状态。若攻击使任一方生命归零，尚未处理力竭触发链时不能继续施毒、回血或返还能量，整个技能回滚；未知冻结后果也在任何伤害或费用实际应用前阻断。双行动执行器可处理明确的回血技能，后手使用先手更新后的生命作实验基数。它仍不构成完整回合。

## 固定连击实验

固定连击编译为 `damage.sequence`，保存来源的 `hits`、`power`、伤害类别和属性。一连击仍保留这一标识；不能把它降为普通攻击，因为 Terms 3005 指明连击数变更只作用于已有连击的技能。该术语没有说明面板威力按每击还是整段计算，也没有给出逐击特性触发或力竭的结算顺序。

执行时必须显式提供 `multi_hit_policy={"power_basis":"source_power_per_hit","timing":"sequential_experiment"}`，或将 `power_basis` 改为 `source_power_total`。这两种都是调用者的实验解释，不是已确认默认值。解释器不会将来源威力乘除连击数；每一击都把原始威力、零起始 `hit_index`、`hit_count` 与所选 `power_basis` 交给未校准的伤害解析函数。

每一击读取前一击后的状态，并各自产生伤害事件；保留技能内操作位置、击次、双方成员、技能槽、源哈希和生命前后值。能量只在技能开始支付一次。第二方行动读取完整第一方技能之后的状态，不共用其他模拟的局面。

任一击异常或返回超过剩余生命的伤害，都会回滚此前全部击次和费用。若在下一击前遇到生命归零，不猜测力竭后续顺序，直接回滚。隔离片段最后一击可返回生命归零的片段结果，但双方行动执行器仍会因完整力竭规则未实现而整体拒绝，不自动跳过对方、换人或判胜。条件连击与连击数修正尚未执行，不能将这些支持范围扩大到所有连击技能。

## 能量条件实验

v4 仅对三条完整来源描述建立 `damage.conditional`：触底强击在来源所述“使用后能量耗尽”时增加 120 技能威力；穿膛在敌方能量不超过 2 时为 5 倍伤害；背袭在敌方能量为 0 时为 20 倍伤害。其他历史条件、任意表达式及附加语句不因此自动获得支持。谓词由固定字段与比较操作表示，不执行输入文本。

来源没有充分定义“使用后”与支付费用的关系，也没有明确另外两条的读取时点。因此必须显式提供 `conditional_policy={"timing":"after_payment_before_damage_experiment"}` 以及 `resolved_energy_cost`（可以为 0），只允许在该实验约定下计算。双方行动执行器从行动明确提供的 `effective_cost` 注入费用，不据基础能耗猜测。来源中的 `after_use`/`unspecified` 标签仍保留，不改写成已确认的付款时点。

条件在真正执行该操作时读取当前状态，不使用提交行动时缓存的值：已发生的支付、返能或回复都会影响该实验分支。例如先手抓挠的付款与返能可能使敌方能量跨过 2 的边界；先手徒长会使原本为 0 的能量发生变化，后手背袭不能继续使用旧零值。这些构造测试不证明真实游戏采用同一判断时点。

威力增加直接形成传给解析器的已解析威力，同时保留 `base_power`；伤害倍率保持基础威力不变，另传 `damage_multiplier` 分数。伤害解析器必须返回已经包含所有所声明修正的实际生命减少量，执行器不会再次乘倍率。事件保留原始条件、实际读取值、是否满足、基础/已解析威力、伤害倍率和实验策略。缺少策略、非法条件、回调异常等均整体回滚，包括已支付费用和另一方已执行的行动。

该实验边界明确排除完整特性、场地、印记、血脉和触发链；这属于组件测试条件，绝不能用于声称完整技能或对战已经还原。冻结的即时力竭阈值和寄生来源尚未实现，因此对应状态赋予会拒绝执行。技能解释器中的中毒/灼烧层数赋予本身不包含后续结算；独立的状态片段现在可在显式伤害解析器、日程和衰减策略下执行，并可与双方行动事务组合，见 [PHASE_RULES.md](PHASE_RULES.md)。这仍不构成完整回合。

## 本机查询接口

- `GET /api/rules/coverage`：逐类实现数量、快照哈希及验证状态。
- `POST /api/rules/skill`，请求 `{"skill_id":7020360,"defender_form_id":3016}`：返回当前 BWIKI 技能、结构化程序、属性关系及仍缺失的完整对战依赖；不返回假伤害或胜率。
- `POST /api/rules/turn-plan`：双方共同前态的行动阶段计划，包含换人资格、印记继承、迅捷顺序、应对及蓄力检查。具体输入与未完成边界见 [PHASE_RULES.md](PHASE_RULES.md)。

基础效果运行器没有接入普通对战网页或训练入口，页面仍以用户记录的实际行动为准。

## 尚需完成的整体目标

下一步需要继续实现有来源支持的回合与切换规则、全技能/特性触发链、面板与伤害精确公式、取整及随机性，并取得对应版本的真实对战记录逐事件校准。当前已查到的更多规则及检索限制见 `verification/bwiki-rule-discovery-20261025.md`。一般能量/魔力/复活默认值不能从特殊特性推断。

规则测试与真实游戏校准严格分开：绿灯测试证明代码边界与指定算例，不证明游戏一致性。正式训练仍被独立校准门槛阻止，完整模拟器目标保持未完成。


## 迅捷攻击与入场执行

v5 支持完整的“造成魔伤，迅捷。”描述，对应当前快照的翼击（7150080）。伤害仍只有一次普通魔法攻击操作；另外保留 `intrinsic_swift=true`、`entry_trigger={"kind":"voluntary_switch","term_id":1005}`、术语 1005 与原始来源。它不是通过删掉所有“迅捷”字样把复杂技能降级为普通攻击。龙卷风的应对条件、风墙的防御及其他迅捷效果仍按各自完整描述判断，不因这次增加而自动可执行。

编译器核对迅捷术语的唯一性、完整原文与已审查哈希。基础运行器也验证这项依赖；正常手动使用翼击只执行一次伤害，不自行触发额外入场动作。主动换人运行器可以在明确的实验时点和独立技能上下文下执行已选中的翼击，具体事务与未完成边界见 [PHASE_RULES.md](PHASE_RULES.md)。伤害仍需调用者提供显式实验解析器，不使用社区候选公式作默认值。

## 能量减少实验

v6 精确编译魔镜（7170280）的完整描述“敌方获得魔防-50%，且失去3能量。”为两个操作：对手魔防的 -50% 有理数修正项，然后 `energy.reduce`。不会只执行其中一项，不从这段文字推断全队扣能、偷取能量或应对条件。来源的“且”没有确认真实结算先后，仍要求 `source_text_order_experiment`。

运行器要求独立声明 `energy_reduction_policy="clamp_to_zero_experiment"`。在此实验策略下，剩余能量不足时截至零，事件同时保留请求扣除量、实际扣除量、前后能量和策略名称；不向施法者返还能量。原文没有明确低能量边界，此策略不是已验证的游戏默认值。魔防仍只记录修正项，不猜测属性叠加公式。

后续技能读取扣能后的当前局面；若后手费用因此不足，现有双方片段执行器整体回滚，不擅自跳过后手、降低费用或代选技能。这是实验 API 的事务边界，不代表真实游戏会撤销先手魔镜；费用不足后的游戏行为尚未实现。任何操作失败均撤销此前的属性修正、扣能和付款。测试中的构造连招只验证解释器状态传递，不冒充游戏合法配招。HTTP 可以在完整显式策略下执行这种不需要伤害函数的片段，但仍没有完整回合或训练许可。
